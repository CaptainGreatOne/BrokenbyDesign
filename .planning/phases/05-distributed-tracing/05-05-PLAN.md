  <action>
Create `grafana/provisioning/datasources/jaeger.yml` with the Jaeger datasource and full cross-linking configuration.

The file follows the same provisioning pattern as the existing `prometheus.yml` and `loki.yml` files in the same directory.

```yaml
apiVersion: 1

datasources:
  - name: Jaeger
    type: jaeger
    access: proxy
    url: http://jaeger:16686
    uid: jaeger
    isDefault: false
    editable: false
    jsonData:
      # Trace to Logs: clicking a trace links to Loki logs filtered by trace_id
      tracesToLogsV2:
        datasourceUid: loki
        spanStartTimeShift: '-5m'
        spanEndTimeShift: '5m'
        filterByTraceID: true
        filterBySpanID: false
        customQuery: true
        query: '{service_name="${__span.serviceName}"} | trace_id="${__span.traceId}"'
      # Trace to Metrics: clicking a trace links to Prometheus metrics for that service
      tracesToMetrics:
        datasourceUid: prometheus
        spanStartTimeShift: '-5m'
        spanEndTimeShift: '5m'
        tags:
          - key: service.name
            value: service
        queries:
          - name: Request Rate
            query: 'sum(rate(http_requests_total{service="${__tags.service}"}[5m]))'
          - name: Error Rate
            query: 'sum(rate(http_requests_total{service="${__tags.service}",status=~"5.."}[5m]))'
          - name: Latency P95
            query: 'histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket{service="${__tags.service}"}[5m])) by (le))'
      # Service map / dependency graph
      nodeGraph:
        enabled: true
```

**Key configuration choices:**

1. **tracesToLogsV2** with `customQuery: true`:
   - Uses Loki's label filter for `service_name` (set by Alloy log collection) combined with a pipeline filter for `trace_id` in the log line content
   - `filterByTraceID: true` enables the built-in trace ID filter
   - Time shifts of 5 minutes before/after the span allow finding logs that occur near the trace
   - The query template `'{service_name="${__span.serviceName}"} | trace_id="${__span.traceId}"'` searches for logs from the same service that contain the trace ID (which we inject in logger.py/logger.go/logger.js)

2. **tracesToMetrics** with predefined queries:
   - Links to the Prometheus datasource (uid: `prometheus`)
   - Maps the `service.name` span attribute to a `service` tag for metric queries
   - Provides three useful preset queries: request rate, error rate, and P95 latency

3. **nodeGraph** enabled for service dependency visualization in the Explore panel

**Note on service_name label:** Alloy/Promtail labels logs with `service_name` based on the Docker container name. The log pipeline in logger.py/logger.go/logger.js also includes the service name in the log text. The `tracesToLogsV2` query uses the span's serviceName to match the Loki label, combined with trace_id content filtering.

  <name>Task 2: Update Prometheus datasource with exemplar-to-trace configuration</name>
  <files>
    grafana/provisioning/datasources/prometheus.yml
  </files>
  <action>
Update `grafana/provisioning/datasources/prometheus.yml` to add exemplar configuration that links metric exemplars to Jaeger traces.

The existing file has:
```yaml
apiVersion: 1

datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    uid: prometheus
    isDefault: true
    editable: false
    jsonData:
      timeInterval: 15s
```

Update it to add exemplar configuration:
```yaml
apiVersion: 1

datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    uid: prometheus
    isDefault: true
    editable: false
    jsonData:
      timeInterval: 15s
      httpMethod: POST
      exemplarTraceIdDestinations:
        - name: traceID
          datasourceUid: jaeger
```

**Key configuration:**

- `exemplarTraceIdDestinations`: Tells Grafana that when a Prometheus metric has an exemplar with a `traceID` label, clicking it should open the Jaeger datasource with that trace ID
- `name: traceID`: Matches the exemplar label name used in all three services (`traceID` is the key set in exemplar dicts/maps in metrics code)
- `datasourceUid: jaeger`: Points to the Jaeger datasource (created in Task 1)
- `httpMethod: POST`: Recommended for Prometheus to handle longer queries (not strictly required but good practice)

**How this works end-to-end:**
1. Services record metrics with exemplars containing `traceID` (e.g., `httpRequestDuration.observe(duration, {traceID: "abc123"})`)
2. Prometheus scrapes metrics with exemplars and stores them
3. Grafana queries Prometheus and receives exemplar data
4. In Grafana panel, exemplars appear as diamond markers on the graph
5. Clicking a diamond opens the linked Jaeger trace view for that specific trace ID
6. This lets the learner go from "I see a latency spike" to "here's the exact trace that was slow"
