**2. Create `services/web-gateway/src/tracing.js`:**
This file is loaded BEFORE the app via `--require` flag. Critical: it must run before Express and gRPC libraries are imported.

```javascript
// tracing.js - OpenTelemetry SDK initialization
// Loaded via node --require before application code
const { NodeSDK } = require('@opentelemetry/sdk-node');
const { OTLPTraceExporter } = require('@opentelemetry/exporter-trace-otlp-http');
const { getNodeAutoInstrumentations } = require('@opentelemetry/auto-instrumentations-node');

const sdk = new NodeSDK({
  serviceName: 'web-gateway',
  traceExporter: new OTLPTraceExporter({
    url: process.env.OTEL_EXPORTER_OTLP_ENDPOINT || 'http://otel-collector:4318/v1/traces',
  }),
  instrumentations: [
    getNodeAutoInstrumentations({
      // Disable fs instrumentation (noisy, not useful for this project)
      '@opentelemetry/instrumentation-fs': { enabled: false },
    }),
  ],
});

sdk.start();
console.log('OpenTelemetry SDK initialized for web-gateway');

// Graceful shutdown
process.on('SIGTERM', () => {
  sdk.shutdown()
    .then(() => console.log('OTel SDK shut down'))
    .catch((err) => console.error('Error shutting down OTel SDK', err));
});
```

**3. Update Dockerfile** to use `--require` flag:
Change the CMD from `["node", "src/server.js"]` to `["node", "--require", "./src/tracing.js", "src/server.js"]`

This ensures OTel SDK initializes before Express/gRPC libraries load, enabling auto-instrumentation hooks.

**Important:** The auto-instrumentation package automatically instruments:
- Express HTTP handlers (creates spans for each request)
- @grpc/grpc-js client calls (creates spans + propagates trace context via metadata)
- Redis client operations (creates spans for Redis commands)
- Node.js http module (creates spans for outbound HTTP)

The gRPC auto-instrumentation automatically injects W3C trace context into gRPC metadata, so order-api receives trace context without manual propagation code.

**1. Update `logger.js` to inject trace context into every log line:**

Import `@opentelemetry/api` and extract active span context in the `log()` function:
```javascript
const { trace } = require('@opentelemetry/api');
```

In the `log()` function, after the timestamp line, get the active span and extract trace_id/span_id:
```javascript
const span = trace.getActiveSpan();
const traceId = span?.spanContext()?.traceId || '';
const spanId = span?.spanContext()?.spanId || '';
```

Add `trace_id` and `span_id` to the log output. Include them as key=value pairs in the details section (before the message), but only when they have values (not empty strings). This ensures Loki can parse them for trace-log correlation.

Example output format:
```
2026-02-11T12:00:00.000Z INFO  web-gateway RequestMiddleware req=abc123 trace_id=abcdef1234567890 span_id=1234567890abcdef Request received
```

**2. Update `metrics.js` to enable exemplars:**

On the `httpRequestDuration` histogram, add `enableExemplars: true` to the constructor options. The prom-client library supports this natively.

On the `httpRequestCounter` counter, also add `enableExemplars: true`.

Do NOT change the `serviceHealthy` gauge (gauges don't support exemplars).

**3. Update `routes.js` to add semantic manual spans and exemplar recording:**

Import the OpenTelemetry API:
```javascript
const { trace, SpanStatusCode } = require('@opentelemetry/api');
```

For each route handler (POST /orders, GET /orders/:id, GET /orders), wrap the business logic in a manual span with semantic naming:

- POST /orders: Create span named `create-order` with attributes `order.product_id` and `order.quantity`
- GET /orders/:id: Create span named `get-order` with attribute `order.id`
- GET /orders: Create span named `list-orders` with attribute `order.limit`

Use `tracer.startSpan()` pattern:
```javascript
const tracer = trace.getTracer('web-gateway');
```

For each span:
- Set `SpanStatusCode.OK` on success
- Call `span.recordException(error)` and `span.setStatus({code: SpanStatusCode.ERROR})` on failure
- Always call `span.end()` in a finally block

**4. Update `server.js` metrics middleware to pass exemplars:**

In the `res.on('finish', ...)` callback in the metrics tracking middleware, extract the active span's trace ID and pass it as an exemplar:

```javascript
const activeSpan = trace.getActiveSpan();
const traceId = activeSpan?.spanContext()?.traceId;
const exemplar = traceId ? { traceID: traceId } : undefined;

httpRequestCounter.labels(req.method, route, res.statusCode).inc(exemplar);
httpRequestDuration.labels(req.method, route, res.statusCode).observe(duration, exemplar);
```

Add the import at the top of server.js:
```javascript
const { trace } = require('@opentelemetry/api');
```

Note: The `.inc()` and `.observe()` methods on prom-client accept an exemplar object as the last argument when `enableExemplars: true` is set on the metric.
