**webhook-receiver/app.py:**
Implement a Flask application that:

1. `POST /alerts` — Receives Alertmanager webhook payloads
   - Parse JSON body (Alertmanager format: `{version, status, alerts: [{status, labels, annotations, startsAt, endsAt, ...}]}`)
   - For each alert in the payload, extract: alertname, severity, service (from labels), summary (from annotations), status (firing/resolved), startsAt, endsAt
   - Store each alert in an in-memory list (max 100 entries, FIFO)
   - Log each alert to stdout: `"ALERT [status] severity=X service=Y alertname=Z summary=..."`
   - Always return 200 OK with `{"status": "success"}`

2. `GET /api/alerts` — Returns stored alerts as JSON array
   - Return the in-memory alert list (newest first)
   - Format: `[{alertname, severity, service, summary, status, timestamp, fingerprint}]`

3. `GET /health` — Returns `{"status": "healthy"}`

Use a threading.Lock for thread-safe access to the alert list. Keep it dead simple — no persistence, no database.

**mock-slack-ui/Dockerfile:**

- Copy server.py and static/ directory
- Expose port 8080
- Run with gunicorn: `gunicorn --bind 0.0.0.0:8080 --workers 1 --threads 2 server:app`

**mock-slack-ui/server.py:**
Flask application with three endpoints:

1. `POST /webhook` — Receives Alertmanager webhook payloads
   - Parse same format as webhook-receiver
   - Store each alert in an in-memory list (max 200 entries, FIFO)
   - Return 200 OK

2. `GET /api/alerts` — Returns stored alerts as JSON (newest first)

3. `GET /` — Serves the static index.html

4. `GET /health` — Returns `{"status": "healthy"}`

Use threading.Lock for thread safety.

**mock-slack-ui/static/index.html:**
Single-page HTML with embedded CSS and JavaScript:

- Title: "Alert Notifications"
- Auto-refreshes by polling `/api/alerts` every 5 seconds via fetch()
- Displays each alert as a card with:
  - Left border color based on severity: critical=red (#d32f2f), warning=orange (#f57c00), info=blue (#1976d2)
  - Resolved alerts use green (#388e3c) border regardless of severity
  - Status indicator: "FIRING" or "RESOLVED" badge with matching color
  - Service name (bold)
  - Alert name
  - Summary text
  - Timestamp (formatted to locale string)
- Cards are in reverse chronological order (newest at top)
- Show "No alerts received yet" when empty
- Show count of total alerts and currently firing alerts in a header bar
- Clean, simple styling: light gray background (#f5f5f5), white cards with subtle shadow, sans-serif font
- No external dependencies (no CDN, no frameworks — pure HTML/CSS/JS)
- No emojis in the HTML
