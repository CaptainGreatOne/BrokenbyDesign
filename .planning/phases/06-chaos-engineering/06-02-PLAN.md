**Chaos State (in-memory dict):**
```python
chaos_state = {
    "latency": {"enabled": False, "severity": None, "delay_ms": 0},
    "errors": {"enabled": False, "severity": None, "error_rate": 0.0},
    "crash": {"enabled": False, "severity": None, "countdown": None},
    "memory": {"enabled": False, "severity": None, "allocations": []},
    "disk": {"enabled": False, "severity": None, "files": []}
}
```

**Severity Presets:**
```python
PRESETS = {
    "latency": {"mild": {"delay_ms": 500}, "severe": {"delay_ms": 5000}},
    "errors": {"mild": {"error_rate": 0.10}, "severe": {"error_rate": 0.50}},
    "crash": {"mild": {"countdown": 10}, "severe": {"countdown": 3}},
    "memory": {"mild": {"size_mb": 50}, "severe": {"size_mb": 200}},
    "disk": {"mild": {"size_mb": 10}, "severe": {"size_mb": 50}}
}
```

Note: order-api uses higher latency presets than web-gateway (500ms/5000ms) because it simulates slow database queries, which are naturally slower than network latency.

**gRPC Server Interceptor Class `ChaosInterceptor`:**
Implement a gRPC `ServerInterceptor` that wraps RPC handlers:

```python
class ChaosInterceptor(grpc.ServerInterceptor):
    def intercept_service(self, continuation, handler_call_details):
        # Get the original handler
        handler = continuation(handler_call_details)
        if handler is None:
            return handler

        # Return wrapped handler that applies chaos
        # ... wrap the handler's unary_unary method
```

The interceptor logic (applied to each gRPC call):
- **Crash check:** If `chaos_state["crash"]["enabled"]`, decrement countdown. When countdown reaches 0, log at ERROR level "Chaos: service crash triggered" with `handler="ChaosInterceptor"`, then call `os._exit(1)` after a brief delay.
- **Latency injection:** If `chaos_state["latency"]["enabled"]`, call `time.sleep(chaos_state["latency"]["delay_ms"] / 1000.0)` before the handler. Log at WARN level "Chaos: injecting latency" with `handler="ChaosInterceptor"` and delay value.
- **Error injection:** If `chaos_state["errors"]["enabled"]`, roll `random.random()` against error_rate. If triggered, set gRPC status to `INTERNAL` with details "Chaos: injected error" and return empty response. Log at WARN level "Chaos: injecting gRPC error".

Use the `json_log` function from logger module for all chaos logging.

**HTTP Endpoint Handlers (using Flask):**
Create a Flask app `chaos_app` with these routes:

**POST /chaos/enable** — Enable a chaos scenario
- Parse JSON body: `{ "scenario": "latency|errors|crash|memory|disk", "severity": "mild|severe", "params": { ... } }`
- Apply preset values, override with params if provided
- For `memory`: allocate `bytearray(size_mb * 1024 * 1024)` and append to allocations list
- For `disk`: write random bytes to `/tmp/chaos-{uuid}.dat` and append path to files list
- Log and return 200 with status

**POST /chaos/disable** — Disable a specific scenario
- Parse JSON body: `{ "scenario": "..." }`
- Reset that scenario's state
- Clean up memory/disk resources
- Return 200

**POST /chaos/reset** — Reset ALL scenarios
- Reset all scenarios, clean up resources
- Return 200

**GET /chaos/status** — Return current chaos state
- Return sanitized state (exclude raw allocation/file references, show counts/sizes)

**`start_chaos_server(port)` function:**
Start the Flask app in a daemon thread on the given port. This replaces the simple `prometheus_client.start_http_server()`. The Flask app should also serve the `/metrics` endpoint by integrating with `prometheus_client`:

```python
from prometheus_client import generate_latest, CONTENT_TYPE_LATEST

@chaos_app.route('/metrics')
def metrics():
    return generate_latest(), 200, {'Content-Type': CONTENT_TYPE_LATEST}
```

This way, both chaos endpoints and Prometheus metrics are served on port 8000.
